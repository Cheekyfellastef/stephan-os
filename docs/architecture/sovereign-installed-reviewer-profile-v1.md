# Original #1574 reviewer: protected installed code custody

This is source for a missing prerequisite of the existing provider-neutral
reviewer. It is not an independently qualified reviewer, a signing service, an
enrollment ceremony, or evidence that Battle Bridge has installed it. The
original #1574 owner and retained reviewer branch continue to own the work.

## Concrete production path

The existing high-risk advisory launcher and Commander Windows calibration
action call one fixed native executable:

`C:\Program Files\Stephanos\SovereignReviewerV1\host.exe`

The Commander registry, displayed command plan and actual spawned executable
are the same. Existing request identity validation, authenticated transport,
maintenance ownership and private pre-spawn failure handling remain in place.
There is no second controller, request queue, lease or arbitrary command API.

The host embeds the installed source commit/tree and an exact 25-file manifest.
It reads its actual location, protected owner and write ACLs, physical parent
directories, file type/link count, machine identity, current Windows token,
installation record, source bytes and separately pinned Node/Git executables.
It retains real read handles that deny replacement/writes. A copied helper,
writable source member, redirect, missing member or wrong hash is a HOLD.

The installed module loader captures the complete 21-module JavaScript graph
before the fixed entry evaluates. The current PR head/base select **data** in
the fixed canonical repository. The original authenticated diff reader rehashes
raw commit/tree/blob objects and retains its existing time, path, byte and object
limits. The local `refs/remotes/origin/<branch>` must match the requested head;
that is a local observation, not a claim of fresh GitHub observation or protected
main admission. Neither the PR's producer implementation nor its worktree is
evaluated. Dirty producer worktree bytes cannot enter the installation package
or the installed execution graph.

The existing advisory engine, Windows calibration engine, remote projection and
coverage engine remain the candidate producers. Model inference still resolves
and binds an observed local digest through the existing Ollama binding code.
An alias/digest alone cannot establish architecture or parameter size, so the
data snapshot reports the neutral class `unqualified-local-ollama`.

## Physical observations and their limits

`--inspect` is read-only and works without a model or network. It reports actual
installed code custody and whether the current token matches the protected
profile SID, differs from the installer SID, or is elevated. Those facts do not
prove that a distinct implementer cannot reenter the reviewer identity. The
result therefore always has `independentPrincipalObserved: false`,
`qualified: false`, `signingAuthority: false`, `reviewerEnrollmentAuthority:
false`, `protectedMergeAuthority: false`, and `physicalCommissioningProven:
false`.

Inference requires a matching, non-elevated actual token. The installer accepts
only an already-existing SID and never creates an account, supplies credentials,
calls RunAs, changes a service, grants signing authority or self-enrolls. If the
existing Commander process cannot run under that token, execution holds; a
caller string or JSON object cannot supply the missing OS identity. Distinct
reviewer identity creation/commissioning remains a separate authenticated
operator/security task. The normal operator can run unqualified candidates
under a deliberately installed matching profile without being called an
independent specialist.

All execution entries, including coverage, require the matching non-elevated
token. The data-only coverage engine is not elevated: physical confinement of
mutable repository metadata is not established by installed code pins. The
hosted elevated fixture proves actual protected profile inspection and refuses
execution; it does not claim a full model or coverage run as that principal.

## Gaming and descendant custody

The native parent owns an atomic Job-list launch with an eight-process and
1 GiB job limit, no breakaway and kill-on-close. Only the fixed installed Node
entry is exposed. The bounded descendants cover its fixed Git reads and native
inspection/governor children. The actual launcher parent is handle-bound;
parent death, timeout, malformed output or gaming preemption cancels the Job.
All source/tool/ancestor pins remain held through observed zero-active-process
drain. Missing drain proof never publishes a candidate.

The native parent reads the fixed physical governor before launch, before
resume, every 500 ms, and after terminal drain. The installed JS model adapter
also checks the native governor before model inventory/generation, throughout
inference and after completion. All existing gaming booleans, the balanced
load mode and the 30-second/five-second timestamp bounds remain mandatory.
`--governor` performs a fresh narrow physical read under its own protected helper
identity; it does not repeatedly hash large Node/Git binaries or cache an
allowance. The parent already retains their complete pins. The JS read has a
one-second timeout; native cancellation continues independently of the JS loop.

The Ollama server is a separate, existing process. This Job does not claim its
process custody or imply that its resource usage has been enrolled or attested.
The existing VR resource governor remains its resource authority.

Exactly one bounded JSON terminal, no stderr, an actual zero exit and confirmed
drain are required. Failed advisory status publication retains a nonzero exit.
Candidate schemas and the existing remote redaction are preserved; no native
identity material is appended to a remotely promoted calibration result.

## Installation and adoption

`build-sovereign-reviewer-installation-v1.mjs --expected-main <sha>` authenticates
the exact current local `origin/main` commit/tree/blob closure and emits a
reviewable immutable PowerShell source artifact and its SHA256. It never
elevates or installs. The whole artifact must pass the existing protected
review and attended privileged installation boundary. Source hashes are not
operator consent and the package does not self-authorize its installation.

The attended installer compiles only the unchanged generic Core Job primitives
and the two reviewer-specific native units beneath an admin-protected staging
directory. It materializes exact raw source bytes, pins them, observes fixed
tool bytes/link counts and creates a machine-bound installation record. It
publishes the helper only after the complete version exists. An upgrade needs
an explicit expected predecessor, retains the old version and atomically
replaces the helper; active read pins prevent replacing an executing version.
Unsafe existing ACLs/redirects or partial versions are refused, never repaired
or recursively removed. Installation reports code custody only.

Exact source paths are classified under the existing offline native installation
owner. Source synchronization never invokes this installer or starts inference.
The existing maintenance runtime profile, closure, witness and signing material
are not reviewer authority and are not borrowed here.

## Deliberate WSL boundary

The old Win32-to-WSL route selected executable reviewer modules from
`STEPHANOS_REVIEW_EXACT_HEAD`. Its exact-object loader protected integrity of
those PR-selected bytes, but did not provide independently installed producer
code. It now returns `WSL_INSTALLED_REVIEWER_PROFILE_REQUIRED` before path
conversion, Git/Node launch, inference or publication. This affects that route's
ordinary review, calibration and preflight calls. The direct Linux candidate
implementation remains unqualified and unchanged. A future WSL route needs its
own protected code, OS/tool and identity custody; a Windows profile or caller
flag is not a substitute. Existing Windows advisory/calibration/coverage callers
use the native profile described above and HOLD while it is absent.

## Validation and remaining commissioning

Portable tests execute actual Git repositories and the installed closed loader:
a PR that replaces producer code is reviewed as inert data, and a changed final
dependency prevents all entry evaluation. Other tests cover request/route
closure, source package hashes, dirty worktrees, source adoption and the existing
Commander ownership/failure paths.

The existing Linux/Windows custody workflow invokes the new tests. Windows
compiles the exact three native units and exercises physical pins, hard-link
denial, all gaming flags/time bounds, token policy, publication failure, parent
observation, real benign child launch, stderr refusal, deadline/gaming
cancellation and descendant drain. An explicitly enabled **GitHub-hosted only**
fixture installs an isolated source profile, reads it through the real native
host, tests altered closure/tool/ACL/copied-helper cases, and removes only its
new fixture namespace. Its receipts remain unqualified and are not Battle
Bridge commissioning proof. Normal tests never install on Battle Bridge.

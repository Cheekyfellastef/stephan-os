## Meter-blackout evidence contract

For each dimension, the original owner must first identify the exact critical operation, existing issue and source writer, principal, current source and served head, resource needs, paid/quota-limited edge, qualified alternate, and whether the operation is intrinsically hosted. Record an independently authenticated before/during/after outage trial with the same original task ID and worker identity; correlate SELECT, CLAIM, physical PICKUP, bounded source/test mutation, independent review, approval and terminal receipts **separately**. A source PR, GitHub CI fixture, queued SELECT, heartbeat, provider-status field or unverified operator assertion is not a physical execution receipt.

An outage trial must be lawful: never evade quotas, use stolen credentials, bypass a subscription, or call a hosted service while asserting a zero-hosted-dependency test. If a provider rate-limits requests, honor Retry-After and stop retries until permitted. If an operation intrinsically needs an external service (GitHub publish, fresh web data, remote message delivery), qualify durable local `PENDING` and safe reconnect behavior instead of claiming offline completion. Remote delivery requires idempotency or independent reconciliation before claiming exactly-once behavior. Gaming or Quest has absolute priority: do not reserve Battle Bridge CPU/GPU/VRAM for inference or build during gaming.

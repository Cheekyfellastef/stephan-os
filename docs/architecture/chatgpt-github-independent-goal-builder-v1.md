# ChatGPT GitHub-first goal build pilot (issue #1574)

## Why this pilot exists
The original Goal Conveyor has a source-custody hold, but a held scheduler or stale lease does not prohibit **separate, unclaimed, GitHub-only source work**. This is a **fourth, manually invoked implementation route**, not a copied worker, Rescue Island clone, Seed Canopy queue, independent daemon, or automatic source-mutation authority. It contributes to #1574, "Provider-neutral build and review continuity when Codex capacity is unavailable". It does **not** mark that goal completed.

## Physical first example
This document is the first independent source change through a ChatGPT authenticated GitHub connector branch, with one isolated branch and a reviewable PR. A branch/commit/PR proves source construction or publication, **not** local worker pickup, independently reviewed completion, protected merge, unattended refill, or Battle Bridge installation. These must be reported separately.

## Selection without the conveyor trap
1. Read the actual goal **number and full title** from GitHub. Identify one bounded task and exact source paths, risk tier, baseline main SHA, test commands, completion contract and operating owner. Keep goal identity; do not fork or mark the original goal completed.
2. Check current open PRs, GitHub branch collisions, previously active work and the **independently observed** original-conveyor, Seed Canopy, Rescue Island and ChatGPT ownership claims for this task and every touched source path. A stale/missing inventory is **UNKNOWN**, not empty. If the task is claimed or ownership cannot be proved, skip *that task* and choose an unrelated eligible task. Never seize/reset an original lease.
3. Reserve a **distinct branch per bounded task**, from an exact checked main head, using an atomic GitHub branch-create operation. If it already exists, investigate/reuse only after verification; do not create another branch/PR or force push. Record task ID, goal and source scope in the PR. Reserve before edits, not by writing to any original conveyor queue.
4. Change only allowed source paths on that branch through authenticated GitHub tools or an independently approved execution host. Do not run source mutation on Battle Bridge without fresh gaming/resource and Windows custody evidence. Prefer GitHub-only, low-risk files for the first pilot.
5. Run tests and diff/CI checks for the exact PR head. Request independently qualified head-bound review, then use the existing protected operator merge route. Changing the head voids review/approval. Do not confuse green CI, mergeability, or a comment with protected approval.
6. After the protected merge, record merged SHA and, if this goal changes Battle Bridge behaviour, verify that installed/served source actually matches. Completion belongs to the original goal only after its own acceptance evidence; a merged child PR alone is not completion.

## No common failure point
- **No polling daemon, controller, worker pool, queue, database, lease, or source-custody writer is introduced** by this pilot. The original #2962/R7 attempt is RETIRED with historical execution outcome UNKNOWN; do not reopen or re-release it. Independently verify any later/current source claim or maintenance custody by its own identity.
- A blocked task must not block another disjoint task. A blocked *review* or GitHub quota also pauses only that PR; retain exact branch/head and switch to unrelated work, not a duplicate builder.
- External limits (ChatGPT usage, GitHub API/CI, independent specialist reviewers and owner-protected merge) remain real. This route is *not* a promise of unattended ChatGPT turns or limitless capacity.
- Gaming has priority: ChatGPT/GitHub-only source planning need not consume the Battle Bridge GPU; no local inference or physical mutation without fresh resource proof.
- The three existing systems (canonical goal, Seed Canopy, Rescue Island) keep their own ownership/receipts. This ChatGPT lane publishes distinct branch/PR evidence; dashboards may **observe** that evidence but must never reinterpret it as canonical physical SELECT/CLAIM/PICKUP.
- Continue small, useful goals if one goal is held. No goal 1290 re-selection spin, no wait-on-the-waiter loops, no heartbeat-as-build claims.

## Pilot acceptance
- Fresh exact-main branch created **without canonical lease acquisition**.
- One actual source edit and isolated source commit, open PR and current-head CI outcomes.
- Qualified independent exact-head review and protected merge **if and when genuinely evidenced**.
- One additional disjoint, unclaimed task built in a separately reviewed PR before claiming the route can process multiple goals; no unattended or parallel-running claim based on this document.
- Report stage truth using: SELECTED, SOURCE_EDITED, PR_OPEN, CI_PASS, REVIEW_PASS, MERGED, LIVE_VERIFIED. Never imply that a later stage occurred from an earlier one.

## First-device capture

The native bootstrap requires a real device credential and fresh possession proof. The original installation page could use an already paired credential but could not register the first one. First-device capture extends the same Commander handler, listener and canonical mobile contracts; it introduces no enrollment pipe verb, scheduler, controller, persistent credential store or installation route.

The source owner first prepares a private `NOT_INSTALLABLE` context from the exact runtime/native source and release package. It binds the HTTPS private origin/RP, operator/machine/generation, source/tree/package/closure/release digests, random user handle and nonce, and at most fifteen minutes of validity. The existing bearer-authenticated owner route can arm one bounded in-memory draft only while the native reader reports missing enrollment. Browser data cannot select those fields. A separate one-use capture capability is delivered privately in a URL fragment, removed from the address bar, retained only in memory and sent only in a fixed request header. It grants draft capture, never Windows authority.

An explicit device gesture consumes creation intent before invoking WebAuthn `create`. ES256, exact private host, user verification and `none` attestation are fixed. Bounded duplicate-rejecting CBOR parsing derives the P-256 public key from the actual attested credential data. A second explicit `get` signs the existing enrollment-setup descriptor and its separate challenge domain. Context, origin, RP, credential ID/key, flags, counters and expiry are independently checked. `none` attestation conveys no hardware qualification. A passkey is created in the authenticator; no Battle Bridge enrollment or receipt key is created during capture.

Interrupted creation, reload, competing credentials and late responses cannot silently create another passkey. Exact repeated captured bytes are idempotent. Refresh reads the original draft without invoking an authenticator. Expiry or process loss discards the draft and leaves an unconfirmed outcome; a new capture requires explicit owner preparation. Only the existing bearer owner can read the completed raw result. No source inputs, machine/SID or administrator material are returned in browser status projections.

The offline captured-bootstrap adapter revalidates registration and the real setup signature, then requires byte-identical output from the original source-bound setup factory. Its result remains `NOT_INSTALLABLE` with all authority flags false. The provisional receipt-key field required by the old proposed-data syntax is explicitly untrusted; only the administrator bootstrap creates and substitutes the actual receipt-only CNG key. Actual enrollment still requires the same operator's enabled administrator token, authenticated source/review/merge evidence and an exact enrollment decision. No incomplete bootstrap may be executed to install the helper first: a failure can leave an intentionally inspect-only partial root.

## Reusable invariant

Use one canonical request/WAL/Job across source preparation, device approval, execution, cancellation and reconciliation. Preserve uncertainty until physical evidence resolves it. Source integrity, authenticated release eligibility, approval consumption, process start, installed bytes and later boot are distinct facts. Transport failure never creates a new authority owner, request, source change or proof.

After root exit, observe the whole native Job through the existing bounded drain budget. A transient live member does not prove terminal failure; only real zero proves drainage, and a persistent member at the deadline still fails closed. Neither a sleep nor child success text substitutes for native accounting.

Terminal outcomes must remain independently reconcilable after helper or network lifetime ends. An ACK from a local client is not durable delivery to the operator. Reopen the same authenticated journal and reobserve protected physical state rather than extending a receipt's lifetime or trusting a Node cache.

The framework owns each asynchronous pipe operation through its native completion and exact single End call, including after a deadline closes the transport. A timeout does not dispose a still-pending APM event or release the original execution owner.

Device registration, verified key possession, administrator enrollment, a protected receipt key and installation approval are separate facts. An inert captured artifact or a passkey prompt cannot supply the missing administrator or deployment authority.

## Expiry before effects and manual partial preservation

The first real administrator bootstrap failed at native descriptor freshness after compiling the protected helper. It had created only the executable and empty state directory; enrollment was not completed. The operational cause was launching after the fifteen-minute pairing window. The source ordering allowed a stale capture to leave protected staging behind. Neither an earlier approval nor an earlier successful capture extends the descriptor's lifetime.

Initial enrollment now compiles the exact authenticated native sources in memory and verifies source membership, actual machine/SID, setup descriptor and device signature before creating the protected root. Admission additionally requires two minutes remaining, using the existing native descriptor validator at both actual time and the budget horizon. The original actual-time validation runs again after protected compilation. A long suspension can still leave a partial root; expiry is never relaxed to make enrollment finish.

The enrollment adapter still refuses every existing root. The separate manual `preserve-battle-bridge-mobile-partial-v1.ps1` adapter can quarantine only the exact fixed failed directory object. It requires actual same-operator interactive administrator identity, local NTFS, protected owners/writers and ancestor pins, no root/ancestor redirection, readable absence of the fixed machine receipt key, installer task and retained mobile genesis, and separately approved exact object/source/target binding. Denied or unknown evidence is never absence. Quarantined contents are opaque evidence: nothing is loaded, traversed for execution, served or made eligible for enrollment.

Preservation requires independently authenticated current merged source and specialist review plus a separate operator decision explicitly approving **opaque quarantine of this exact directory object and all its live child objects and named streams**. The approval fingerprint binds repository/source head/tree, actual machine/SID, directory volume/file identity, retained original parent/ancestor identities, protected ACL observation, operation and fixed destination-name derivation. It is not approval of an asserted immutable inventory. New contents/streams are included in that explicit whole-object preservation scope; they remain untrusted. An old exact-byte enrollment or helper-only recovery decision cannot authorize it.

The adapter reuses the canonical same-parent rename principle in `scripts/windows/SovereignFileMoveV1.cs`: retain the verified DELETE-capable directory handle and protected parent/ancestor handles, call native `FileRenameInformation` with `RootDirectory=NULL`, one validated fixed sibling basename and `ReplaceIfExists=false`. A non-null `RootDirectory` can reopen a destination by pathname and is not admitted. No absolute destination path is resolved, no destination container is created, and no directory contents are copied or deleted. The kernel rejects a concurrently created destination, including a junction, without adoption or overwrite. The native root identity and final name are read back through the same retained handle; a parent-relative native open must report authentic `NAME_NOT_FOUND` for the original name. Access denied and unknown errors remain held. Existing open children can make NTFS refuse; no process is closed or sharing protection weakened to force progress.

This contract preserves every child and stream as part of the approved object. It makes no atomic-content-CAS, all-stream-immutability, quarantine-content-trust or installation-health claim. A partial/uncertain rename is inspect-only and cannot automatically retry or restore. No file or directory deletion, recursive cleanup, ACL change, key/task/log mutation, executable load, enrollment, installation or reboot is provided. The private factory authenticates exact Git membership and produces immutable `NOT_INSTALLABLE` payloads with every authority flag false; its explicit whole-object operation/gate cannot be supplied by a caller path or approval boolean.

After preservation, fresh device proof and fresh exact enrollment approval are still required. Runtime installation remains a separate gate. No reboot is granted. This manual adapter is not a runtime command, pipe operation, controller or addition to either native/runtime closure.

Reusable lesson: validate expiring cryptographic prerequisites before protected staging and retain live-time validation at the effect boundary. Bind recovery authority to the actual semantic object being preserved. Directory and stream sharing do not make a whole-content snapshot atomic, and readback cannot prevent an unauthorized destination traversal. Reuse Sovereign's `BOUNDED_PRE_POST_OBSERVATION_NOT_ATOMIC_CONTENT_CAS` distinction and same-parent native rename; require explicit new whole-object quarantine authority instead of silently promoting inventory into a grant. A failed attempt never converts enrollment approval into recovery or retry authority.

The fixed Task Scheduler absence boundary qualifies only HRESULT `0x80070002`
returned as `COMException` or `FileNotFoundException`. Windows may marshal the
same native missing-task result as either managed exception. Denied, unknown,
other exception classes and other HRESULTs remain failures; a returned task
remains present. Real Windows COM regression evidence must accompany this
mapping, alongside adversarial error-class/HRESULT tests.


### Structural review: explicit retirement and fresh enrollment

This is a design proposal, not an admitted retirement or recovery capability.
The current key and partial root remain untouched. Original goal, owner, branch,
review/source/operator gates and no-reboot constraint remain canonical.

The actual Windows failure reached strict fixed receipt-key finalization, then
stopped before `enrollment.json` on ambiguous six-argument FileStream binding.
Read-only administrator observation verifies the present key policy/public
fingerprint and present helper bytes, plus absent task/mobile genesis. It does
not authenticate their historical origin. No predecessor key-creation or output
compilation receipt was emitted before failure. Structural findings 4579816234
and 4579816238 therefore prohibit adopting either object as authenticated prior
enrollment artifacts. A current hash, source records or a new operator fingerprint
must never be relabelled as missing historical provenance.

The rejected key-preserving resume proposal is replaced by an explicit current-
object retirement operation followed by opaque quarantine and wholly fresh
enrollment. This requires new source review/approval and a later, separate exact
live decision. General completion requests do not authorize key destruction.

#### Fixed retirement boundary

- Observe only the fixed Microsoft Software KSP machine key name, using the
  existing native strict P-256/signing/nonexportable/admin ACL verifier. Bind its
  actual public fingerprint, current source and actual machine/operator to a
  distinct RETIRE_UNQUALIFIED_MOBILE_RECEIPT_KEY_V1 decision. There is no key-name,
  provider, path, command or export selector. Public fingerprint is identity of
  the object to destroy, not proof that it came from the failed request.
- Require actual same-operator interactive WindowsPowerShell administrator,
  current authenticated merged source, protected fixed root/parent/state pins,
  no enrollment/release/certificate/authorization/WAL files, exact root/helper-
  plus-empty-state shape, absent fixed task and readable empty mobile anchor
  subset under the existing retained channel policy. Denied/unknown/later-stage
  state is inspect-only. No signed or qualified enrollment may be retired here.
- Reuse the existing native first-instance protected PipeName exclusion through
  its current strict ACL factory. Manual mutation holds that same canonical
  singleton object without accepting peers or exposing a runtime command. Fresh
  manual enrollment must use the same exclusion. This is transient exclusion
  inside the existing owner boundary, not a controller, worker, queue or lease.
- At execution reopen exactly the fixed key, revalidate and compare the approved
  public identity through the retained key object, then delete only that object
  through its handle. Do not reopen by a caller name, export private material,
  widen policy/ACL, overwrite or recreate a key. Microsoft documents NCryptDeleteKey
  as consuming the opened key handle; CngKey.Delete removes its associated object.
  Reconcile authentic key absence and unchanged filesystem/native records. Failure
  or uncertain readback is UNKNOWN/inspect-only, never an automatic retry.
- Key retirement does not move/delete a file or install anything. After proven
  retirement, the existing separately approved exact-directory-object opaque
  quarantine adapter can preserve the failed root with all then-linked children
  and named streams. The old helper is never loaded, executed or adopted. Fresh
  enrollment compiles a new helper from authenticated current source.

Primary contracts: [NCryptDeleteKey](https://learn.microsoft.com/en-us/windows/win32/api/ncrypt/nf-ncrypt-ncryptdeletekey)
and [CngKey.Delete](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.cngkey.delete).

#### Fresh enrollment as a bounded saga

Use explicit .NET enum types for file mode/access/share/options. Exercise the
actual production write function under WindowsPowerShell temporary fixtures,
including all closed file names, exact readback and create-new collision refusal.
No production key/root is used by these fixtures.

Extend the canonical native enrollment qualification/anchor context, not an
independent journal or controller. The new version must carry the exact fresh
setup descriptor, device proof, source/package/release and operator/machine
binding into every irreversible enrollment boundary. Native code revalidates
the real current clock immediately before each authorization signature, genesis
append and certificate seal. A newly stamped signature alone is not fresh proof.
Signed durable evidence binds the same authorization-context digest, its validity
window and native acceptance time to the WAL header/genesis and certificate.
Runtime qualification independently verifies the same context and signatures;
absence, mismatch, expired-at-signing proof or an unsupported old partial state
must fail closed. Old unqualified binaries are never retained as new helpers.

The proposed versioned model must explicitly define this transition matrix:

| Durable boundary | Required positive proof | Injected interruption/uncertainty |
| --- | --- | --- |
| authenticated preflight/exclusion | source/device/target/time verified, no protected effects | refuse before mutation |
| root and helper compilation | actual compiled helper/current source and pinned protected estate | hold; no adoption/retry |
| strict new receipt key | fixed policy/ACL/public identity, create-new only | key-only hold; only separately approved retirement can apply |
| enrollment/authorization/release files | exact closed create-new files and native authorization context | any partial file state holds; retirement refuses |
| authorization-bound WAL header | same binding/context and exact disk readback | partial WAL holds; never reset/recreate |
| fresh signed genesis | native current-time check, same context digest, retained append/readback | uncertainty holds; never retry append |
| certificate seal | native current-time check, same context/helper/source and signature readback | uncertainty holds; never reseal/overwrite |
| fixed task registration | exact executable/arguments/principal/ACL and on-demand-only settings | any existing/partial task holds |
| independent qualified readback | source, actual key/helper, authorization, WAL/genesis/certificate/task agree | no READY or install authority without proof |

Actual positive Windows production-path fixtures must traverse this complete
matrix before another phone pairing is requested. Inject a stop/error/unknown
after every durable boundary and prove that every unsupported resulting phase
is refused on subsequent admission. Include model/property tests for illegal
edges, replay, collision, source/key/context substitution and temporal suspension.
Synthetic/temporary fixtures never qualify the production key, source or device.
Fixtures may use the existing private native callback/pipe seams and isolated
test keys/paths; they may not introduce a shipping arbitrary-key/path or fixture
authority bypass. Final live acceptance remains independently observed.

The current recovery scope is exact unqualified-key retirement and fresh setup,
not general later-phase repair. Unsupported post-file/WAL/genesis/certificate/task
partials remain typed inspection holds; this bounded debt is explicit. There is
no key adoption, implicit migration, reset, cleanup, automatic retry, new runtime
provisioning verb, installation or reboot. Installation approval/receipts and
later-boot physical qualification remain separate from enrollment success.

# Original attempt lease safety (#2961)

The 11 October 2026 physical original r7 lease has no canonical execution receipt and no exact r7 terminal queue pair. Its reported HEAD_SHA, LEASE_KEY and PR_NUMBER mismatches come from legitimate intake revision r0. Four other historical terminal records are already excluded. Accepting canonical r0 as historical yields five older records and ORIGINAL_EXACT_TERMINAL_PAIR_NOT_FOUND; it does not recover missing r7 proof.

Structural review of release entry points found a second issue: PR-head dispatch releases a parked or terminal phase's lease directly, while the expired-repair reconciler requires original terminal evidence. Thus parking/STOP could accidentally escape the stricter original-owner guard. The repair requires every exact-lease execution chain to end in a terminal receipt, separately resolves and verifies the source action from the consumed canonical AGENT_RESULT_RECEIVED event and its processed event ID, and requires complete original queue proof. Provider result IDs are opaque; they are never parsed as execution IDs or normalized by stripping provider prefixes. The unique consumed result event binds the provider result namespace to the queue action namespace under the mission lock. Missing, duplicate, unprocessed or wrong-mission bindings HOLD. A later completed PR check cannot conceal a missing or active source execution. The source dispatch can predate the PR-head lease; its original revision/lease binding is inspected without rewriting its head or PR identity. Release is serialized against canonical mission re-entry/dispatch with the existing mission-state precondition lock. The canonical lease operation lock still owns exact lease release and durable release-marker recovery. Unknown proof retains the lease and prevents refill.

This change does not introduce an orphan-release authority. On this physical r7 attempt, missing authentic terminal proof must continue to HOLD. A future orphan quarantine requires separately reviewed, exact operator authority; positive detached-writer exclusion; durable original-attempt fencing consulted by publisher, claimant and source guard; compare-and-swap against the original lease bytes/revision; immutable forensic audit; restart/replay proof; and guarded canonical release. The observed unreadable live process command lines cannot be counted as zero writers.

PARKED_DEFERRED must preserve the same canonical goal, old attempt/PR and receipts, remaining acceptance scope, blocker history and retry budget. Re-entry must require an actual verified capability/blocker revision change plus current-main reconciliation, qualified capacity and a new legal claim. Already merged #3000 remains accepted source work. No new scheduler or daemon is required.

Validation covers canonical r0 history, noncanonical r00, poisoned current r7 identity, duplicate pairs, missing/nonterminal receipt, a later completed check hiding an active chain or missing source result, native-prefixed and opaque provider result IDs, canonical consumed-event ambiguity, cross-revision source receipts, STOP/parked phases, source/PR/lease mismatch, unknown/queued writer activity and concurrent mission re-entry. Independent exact-head security review is required before deployment.

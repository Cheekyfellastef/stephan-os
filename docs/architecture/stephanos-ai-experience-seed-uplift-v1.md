## Continuous improvement route

```
Stephanos AI conversation / mobile browser / shared thread / hosted bridge
  -> observed failure with fresh timestamp and evidence
  -> existing Shared Workspace learning/capability-gap record
  -> conversational seed growth projection (#2798)
  -> existing Flywheel Learning Goal Bridge
  -> existing canonical goal owner search, dedupe and bounded admission
  -> goal conveyor SELECT / CLAIM / execution / proof
  -> governed review and protected merge/deploy
  -> real iPad/phone/Battle Bridge replay
  -> retained learning and the seed's next proved growth rung
```

When the proof is missing, the seed stays UNKNOWN or shows the missing/blocked
state. It must never claim that CI or GitHub publication alone fixed an iPad.
No automatic resubmission of an uncertain chat turn. Provider-neutral routing,
operator approvals, secrets and protected-branch rules remain unchanged.

## Regression and growth signals

Monitor or accept **evidence-backed** reports of:
- a conversation lost after page close/reload, backend restart or browser crash;
- mismatched canonical thread IDs across iPad and Battle Bridge;
- unconfirmed/duplicate operator turns after a timeout or reconnect;
- iPad and phone inability to scroll, access the composer, or focus correctly;
- increasing DOM/render memory pressure or degraded responsiveness in long chats;
- incorrect/missing HTTPS bridge reachability and hydration freshness;
- a hosted workspace serving stale assets or a different canonical UI head;
- incorrect model routing or hallucinated project state.

Each reported failure should carry a privacy-safe classification, canonical
owner goal, timestamp, source/served identity when available, and independently
verifiable proof. Private conversation text and credentials do not belong in
telemetry. Machine-readable failure evidence must take precedence over
optimistic prose.

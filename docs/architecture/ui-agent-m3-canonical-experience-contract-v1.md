# UI Agent M3 Canonical Experience Contract V1

## Purpose

M3 turns the evidence-backed M2 experience inventory into one canonical cross-surface design map for Stephanos. It is a product contract, not a renderer, redesign worker, deployment path or source-mutation authority.

## Admission

M3 accepts only an M2 inventory that is valid and explicitly reports `M3_PUBLISH_CANONICAL_EXPERIENCE_CONTRACT_AND_DESIGN_MAP`. All 20 canonical product/presentation surfaces must be present and the M2 coverage summary must report complete canonical coverage with the exact same canonical surface identities.

The caller-owned M2 packet is recursively reduced to the bounded fields M3 actually needs before any admission decision. Top-level, inventory, surface and coverage records must be ordinary data-only records. Surface lists and coverage lists must be dense standard arrays. Accessors, sparse collections, custom prototypes, symbols and revoked/uninspectable proxies fail closed without executing caller getters. The accepted snapshot is detached from later caller mutation.

## Canonical experience language

Every mapped surface inherits the same high-level contract:

- summary-first information hierarchy;
- one clear primary action with bounded secondary actions;
- thin shared surface/border language;
- subtle motion with reduced-motion fallback;
- explicit loading, empty, error and offline truth;
- responsive/touch/keyboard continuity appropriate to the presentation;
- task/context continuity rather than per-device reinvention;
- spatial readiness without claiming a live Quest experience.

This deliberately defines coherence without forcing every surface into identical layout.

## Proof plan

M3 carries forward the canonical M2 proof classes as an explicit unsatisfied proof plan. Source publication does not mark desktop, tablet, phone, keyboard, touch, reduced-motion, loading/error/offline, Windows Edge or spatial/Quest evidence as passed.

## Authority

The contract is advisory and read-only. Source mutation, implementation, merge, deployment, runtime mutation and product authority are all false.

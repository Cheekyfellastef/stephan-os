# Protected Workflow Dispatch Acceptance V1

The repair is accepted only when the existing protected merge mailbox operation can take a clean exact-head Independent Merge Security Review and dispatch the canonical `Protected Operator Merge Queue Boundary` workflow with exact immutable inputs, while retaining the existing qualified-bootstrap path unchanged.

Required invariants:

- no new mailbox operation;
- no direct PR merge from the new clean path;
- no direct write to `main`;
- no ruleset or protected-environment bypass;
- exact PR/head/base revalidation before dispatch;
- exact hosted-check revalidation before dispatch;
- exact independent review run/job/artifact/payload revalidation before dispatch;
- `clean-independent`, high-risk specialist assurance, zero findings for the clean path;
- exact source head tree derived from GitHub, not authored by the mailbox caller;
- only `operator-merge-approval-gate.yml` may be dispatched;
- only `user-owned-protected-squash` may be selected;
- distinct explicit approval token for workflow dispatch;
- the workflow remains responsible for its own evidence, protected approval and squash mutation.

This capability is a control-plane repair needed to continue Forge commissioning when the interactive GitHub connector lacks native workflow dispatch.

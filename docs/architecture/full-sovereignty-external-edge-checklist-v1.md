## Inventory and evidence rules

The existing `FULL_SOVEREIGNTY_DIMENSIONS_V1` remains the dimension roster; this checklist does not create another registry, controller, approval plane, build queue or lease. For **each** dimension below, the existing owner must identify:

1. Current named executable/service and machine or external principal, exact source path and deployed head.
2. Any external provider, Internet route, quota, license, cloud API, hosted review, relay or proprietary runtime required for its *critical path*. Clearly distinguish inherently external operations (such as publishing to GitHub) from avoidable coordination dependencies.
3. Current qualified operator-controlled implementation, if one exists, and the same operation's behavior with that external edge offline.
4. Correlated evidence: observed timestamp, exact source/runtime identity, command or test ID, trusted immutable receipt/proof reference, reviewer or physically authenticated witness where needed.
5. Degradation plan: durable queue/record identity, no duplicate execution during reconnection, bounded retry, preservation of approval and resource ownership, and explicit user-visible state.
6. The **original** owner issue/PR and smallest missing capability or source repair. Do not treat seed title, a document, a new issue, a PASS-looking JSON field or a healthy heartbeat as execution proof.

Until a trusted witness exists, status is `UNVERIFIED`, not `PASS`. A failed external-offline trial is `FAIL` with a typed blocker; a missing prerequisite is `WAITING_FOR_PREREQUISITE`. Review/CI/merge/source/physical runtime are distinct proof stages.

## Per-dimension verdict contract (not a new registry)

For every row, the original owner must attach an evidence packet to the **existing** canonical seed/goal record. A reviewer should be able to reproduce the verdict without relying on this document, a self-declared status flag or a UI card. The packet identifies the dimension, owner issue and task, exact source and served head, principal and physical worker (when applicable), tested external edge, deliberate outage window, trusted witness/receipt reference, result, independent reviewer, and remaining dependency or next original-owner repair.

- **`UNVERIFIED`**: no independently authenticated, current, source-bound offline trial exists. Passing CI, a source proposal, a selected task or an accepted dispatch never changes this verdict.
- **`WAITING_FOR_PREREQUISITE`**: a named immutable approval, lease, security, Windows custody, gaming-governor or qualified-provider gate prevents a safe trial. Record the first gate and original owner; do not manufacture a capability gap.
- **`FAIL`**: a qualified offline trial shows loss, duplicate execution, unsafe resource use, unverifiable custody or inability to recover. Preserve the failing trace and route the smallest correction to its existing owner.
- **`PASS`**: the same qualified operation was independently observed both with the edge present and absent, with correct bounded behavior, matching source/runtime identities and terminal receipts. For inherently external operations, offline `PENDING` with durable identity and guarded delivery on reconnect is acceptable only when remote idempotency or independently verified reconciliation prevents duplicates. Without remote idempotency or independently verified reconciliation, report delivery as `UNVERIFIED` rather than asserting exactly-once completion; an offline claim of remote completion is never proof.

For the worker-endurance dimension, prove both seed workers were **physically executing at the same time**, with distinct canonical seed/task IDs, one mutation writer and source scope per task, authenticated same-worker SELECT→CLAIM→PICKUP chains, overlapping execution timestamps, disjoint resource custody and independently checkable source/test mutations and terminal receipts. Two sequential tasks, a CI fixture, a queued dispatch, or one worker handling two labels cannot satisfy parallel pickup. An independent unattended repeat must preserve the same admission and gaming safeguards.

A verdict must name the **specific function and external edge tested**. One passing dimension cannot certify the other fifteen, and a rung-1 checklist cannot satisfy the later full-blackout endurance rung. Do not advance #3026 from document publication, ordinary PR checks or an unreviewed evidence packet alone.

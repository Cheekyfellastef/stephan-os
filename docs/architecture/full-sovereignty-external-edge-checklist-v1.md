## Inventory and evidence rules

The existing `FULL_SOVEREIGNTY_DIMENSIONS_V1` remains the dimension roster; this checklist does not create another registry, controller, approval plane, build queue or lease. For **each** dimension below, the existing owner must identify:

1. Current named executable/service and machine or external principal, exact source path and deployed head.
2. Any external provider, Internet route, quota, license, cloud API, hosted review, relay or proprietary runtime required for its *critical path*. Clearly distinguish inherently external operations (such as publishing to GitHub) from avoidable coordination dependencies.
3. Current qualified operator-controlled implementation, if one exists, and the same operation's behavior with that external edge offline.
4. Correlated evidence: observed timestamp, exact source/runtime identity, command or test ID, trusted immutable receipt/proof reference, reviewer or physically authenticated witness where needed.
5. Degradation plan: durable queue/record identity, no duplicate execution during reconnection, bounded retry, preservation of approval and resource ownership, and explicit user-visible state.
6. The **original** owner issue/PR and smallest missing capability or source repair. Do not treat seed title, a document, a new issue, a PASS-looking JSON field or a healthy heartbeat as execution proof.

Until a trusted witness exists, status is `UNVERIFIED`, not `PASS`. A failed external-offline trial is `FAIL` with a typed blocker; a missing prerequisite is `WAITING_FOR_PREREQUISITE`. Review/CI/merge/source/physical runtime are distinct proof stages.

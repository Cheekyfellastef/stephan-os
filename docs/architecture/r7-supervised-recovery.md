## Implementation and boundary

The supplied preparation patch was adopted at source head `5c82ba640dcc2ad2339aff94db7bac097c10fd57`, then extended into the existing mission store, cancellation fence and canonical lease reconciler. There is no second controller, worker, scheduler, queue or lease database. Ordinary strict quarantine still uses its original proof functions.

The private `scripts/supervised-r7-recovery.mjs` entry point resolves the installed canonical roots. It accepts a bounded JSON stdin object with only `request` and `approvalCommentId`. The request contains exactly `requestId`, `commandId`, `sourceRevision` and the SHA-256 of the **entire original lease JSON record**. It accepts no paths, approval booleans, readers, shell commands or restart options. The production implementation reads the existing mission/lease/queue stores, installed worker heartbeat, Git state and GitHub evidence service.

1. `describe-maintenance` reads the exact R7 mission and lease and returns the maintenance packet and digest without mutation. The target is fixed to mission `critical-2962-elastic-goal`, revision 7, lease `critical-2962-elastic-goal-r7-lease`, original branch `openclaw/elastic-goal-2962` and PR #2987, with the observed original commit/worktree and installed source revision. An existing maintenance reservation is also digest-bound.
2. `maintenance` authenticates a direct owner-authored, unedited GitHub decision on #2961 and reserves maintenance in the existing mission record. The mission lock excludes source apply/rollback and remote publication while the reservation is installed. Existing claim, dispatch, retry, result and commit guards reject the reserved attempt. No process is killed and no global worker is stopped. Previously running code must have drained cooperatively: subsequent stages require an affirmative, fresh, idle heartbeat from the exact installed revision after the reservation and no original pending/processing work.
3. `preserve` copies current dirty and untracked bytes, staged changes, queue/artifact/outbox files, mission/event records and available execution receipts into an exclusive artifact directory; it creates and verifies a Git history bundle. It compares a second inventory before publishing the manifest. Missing, linked, oversized or changing evidence holds recovery. Nothing is deleted or overwritten. A partial/expired attempt remains preserved; a replacement command requires a new exact maintenance decision and retains the prior reservation in mission history.
4. `prepare` runs the supplied repeated-observation preparation contract against those real readers and writes an immutable exact recovery packet. The packet has a maximum ten-minute evidence window.
5. `retire` authenticates a separate exact retirement decision under the existing mission and lease locks, rechecks target and preservation after authentication, and commits approval consumption and the cancellation journal together in the mission state. It repairs an interrupted audit append before canonical release. The existing reconciler then verifies the consumed decision, current source inventory, preserved bundle, idle worker and empty original queues before invoking the existing whole-record comparison and release-marker protocol. Renewed or changed leases are held. A restart can finish the **same** consumed decision after its approval window; it cannot authorize a new operation. The script never restarts or admits a worker.

An approval comment contains exactly one `stephanos-supervised-r7-approval` JSON fence. Its closed fields are `schemaVersion: stephanos.supervised-r7-operator-approval.v1`, the packet's `purpose`, `packetDigest`, `requestId`, `commandId`, `sourceRevision`, `originalLeaseDigest`, `lowerAssuranceExplicitlyAccepted: true`, and `expiresAtUtc`. GitHub must report the exact owner ID/login, `OWNER` association and unchanged creation/update timestamps. Comments created through an app are rejected as operator decisions. A preparation or coordination comment is never an approval. Expiry must be at most ten minutes after approval and no later than the retirement packet's expiry.

## Limits and live sequence

The maintenance boundary relies on the reviewed cooperative worker and existing publication routes obeying the canonical store. A known competing writer, unexpected Git change, stale/mismatched worker or unexplained original queue item remains a blocker. It does not inspect or exclude arbitrary privileged Windows processes or retained kernel handles. File flushes and the existing journal/atomic replacement protect process interruption; this is not a claim of independently certified power-loss or Windows kernel recovery.

Protected integration, current installed source/custody evidence and exact maintenance/recovery approvals precede live execution. A generic chat approval or an earlier merge approval is insufficient. The private CLI is deliberately not an arbitrary public-mailbox execution surface. Use an already-authorized local/Sovereign execution route; absence of that route is an execution blocker, not evidence of success.

After verified exact release, the existing admission machinery may admit one separately authorized, small, reversible source/test task to an existing worker. Acceptance requires its actual pickup, useful diff, passing tests and verified commit. None of preparation, cancellation, release, dispatch, review or this document proves that first build. Expansion of resource-disjoint capacity follows that result and preserves gaming priority.

## Proposed invariant

Canonical authority-bearing Git commands must execute against the fixed canonical common .git directory and work tree, with a closed, enforced configuration policy. Their execution must not consume any worktree-specific configuration. The repository configuration and registrations remain unchanged for other checkouts and applications. A source observation does not release the maintenance hold or attest another writer's exclusion.

The original command-override proposal is REJECTED. Native Git 2.53.0.windows.2 still reads both main and linked worktree settings when false overrides are supplied in argv and environment. Independent review4372116976 confirms the bootstrap ordering defect. No validation exception may rely on those overrides.

The replacement is a private, temporary administrative context for the existing canonical source collector. It does not alter the shared Git execution policy or any repository configuration. After the original canonical topology is verified, capture bounded ordinary HEAD and index bytes with their native identities and hashes. Create a fresh private directory outside the repository containing only their copies, a fixed commondir pointer to the authenticated canonical .git directory, and an empty private config.worktree file. Every source-probe command uses the existing fixed Git executable/environment plus this private --git-dir and the unchanged canonical --work-tree. The canonical common config, objects and shared refs remain the original repository's; only per-worktree administrative input is isolated. No new linked-worktree registration, branch, source writer or source/index mutation is created. The existing fixed fetch remains the same explicitly bounded remote-ref observation/update.

Native disposable proof succeeded: an original config.worktree sentinel is visible normally, absent through the private context; branch remains main, HEAD is identical and tracked status is clean. The original file remains byte-identical, and a fixture helper is not executed. This is design evidence, not production source admission or custody proof.

Context qualification must derive from the actual native factory, not a serializable caller boolean. Bind it to the exact canonical root, captured HEAD/index bytes and private directory/file identities. Verify original snapshots and empty private configuration before each command and at closure. Additionally require Git's own worktree-config listing through that context to be empty before status/fetch and afterward. The original canonical topology/config/index/HEAD/origin before/after checks still apply. Cleanup is limited to verified owned metadata; unknown identity/content refuses cleanup and authority rather than deleting an unrelated path.

Review4372141926 identifies a separate index equivalence requirement: a newly timestamped byte-identical copy can disable Git's racy-entry content checks. Before ANY Git command can read the private index, assign it a strictly positive whole-second timestamp at least one second older than the captured original index timestamp. Read back native metadata and require that the actual private timestamp is no later than the captured original; unrepresentable/invalid timestamps deny the context. Bind original mtime as well as bytes/inode, and require private bytes/inode/mtime to remain unchanged at every boundary. This deliberately makes racy detection at least as conservative as the original index; never accept the fresh copy's default newer timestamp. Retain disabled optional index writes. A same-size edited-file fixture must prove canonical dirty / naive-newer-copy clean / qualified-older-copy dirty on both Linux and native Windows before implementation acceptance.

Only a qualified live private context can permit exactly one valid boolean extension declaration in the common config audit. Default raw validation still refuses it; every other unsafe key/category, duplicate/malformed declarations and noncanonical origins remain denied. The public adapter accepts no caller-selected directory, executable, arguments, config, environment or alternate command lane. Existing callers of the shared resolver retain their current behavior. The bounded common-origin/config fetch contract does not acquire checkout, commit, process, lease or service authority.

## Required adversarial evidence

- Real Git fixtures with extension enabled, registered linked worktrees, and hostile current or linked config.worktree files: private-context commands must observe only canonical common configuration and must not execute helpers, filters or alternate transports. Retain the failed override-only mechanism as a negative native regression.
- Repository and worktree files remain byte-identical after observation; no registration, index, source lease, maintenance custody or service changes.
- Default configuration validation still refuses the extension; only the actual live native context admits its bounded declaration. Plain objects, closed contexts, mismatched roots, changed originals/private metadata and nonempty private worktree config remain denied.
- Duplicate/malformed booleans, missing/foreign context, noncanonical/multiple origins and other unsafe keys stay denied. Missing, linked, oversized or unsupported index/HEAD metadata fails closed. The factory never copies source files or creates a new authority root.
- Racy-index stat-cache matches cannot hide changed bytes: verify the explicit canonical/naive-copy/qualified-copy control above. Timestamp rounding, invalid or zero epochs, changed original mtime, and any private index refresh must deny qualification rather than weaken content checking.
- Environment injection cannot select another Git context or worktree config. Source collector supplies the same qualified context at both existing configuration boundaries; mid-observation source/config/index/topology changes remain denied. Original per-worktree config is never used by the private Git process, even if changed concurrently.
- Native Windows readback must prove source admission using the exact protected installed head without deleting metadata or unsetting the repository option. Linux/Windows regressions and independent exact-head Windows/security review precede protected integration.
